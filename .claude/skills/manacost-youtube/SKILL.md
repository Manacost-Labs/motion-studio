Студия `video/src/studios/manacost-youtube`: шаблон `template/` (подробности каждой детали — `template/README.md`), ролики `yt-<тема>/`. ## Как заполнять конфиг (коротко; подробно — examples.md)

- **Порядок сцен** заготовка ставит сама: `hook` → `intro` → колоды с последнего места → `divider` перед №10 и №5 → №3–№1 → `manacostOutro`. Не переставлять.
- **`at`** (и `to`, `teaseAt`) — кусок текста `vo` дословно, 1–4 слова. По нему элемент появляется в момент, когда диктор это говорит.
- **Тезисы** `points`: 2–3, `text` ≤ 28 знаков (вывод, а не пересказ), `detail` ≤ 45. **Матч-апы** `vs`: *какие* показывать — только названные в статье (нет в статье — `vs: []`); их `at` — как у всех привязок, кусок `vo`, где диктор о них говорит. **Карты** `cards` — заготовка берёт из упоминаний; `ink: true` — 0–3 на колоду (больше трёх — предупреждение), только у карт, которые диктор называет главными, лучшими, ключевыми.
- **`teaseAt`** во вступлении — фраза, где диктор намекает на лидера («на вершине», «кто же на первом месте»): в этот момент появляются размытые постеры топ-3.
- **Числа** на экране (`value`, `results`, тезисы) — только из статьи или из `meta.json`. В `vo` — словами. Цифра из `meta.json` — с источником в тексте или пояснении: «винрейт 54,8 % по данным HSReplay в Легенде». Колоды с `reliable: false` (меньше тысячи игр) — без цифр.
- **Произношение**: общий словарь студии — `src/studios/manacost-youtube/pronounce.json` (`"ДК": "дэ-ка"`, имена с апострофом), подмешивается во все ролики сам. Новое сокращение или имя, которое диктор читает неверно, — **в словарь** (пригодится следующим роликам); в `pronounce` конфига — только слова этого ролика. `yt-qa` перечислит недостающие, а после записи — «термин звучит иначе».
- **`ambience`** — тихий фон под всем роликом: `['lib/amb/tavern-crowd.wav', 'lib/amb/tavern-fire.wav']` (гул таверны и камин, бесшовные петли). Проба 03.10 — ставить по умолчанию, когда пользователь одобрит (см. `TASTE.md`).
- **Обложка** `thumb`: `title` — две строки, в каждой ≤ 14 знаков (буквы, пробелы и знаки; `\n` — перенос, не считается): «15 колод» — 8, «для Легенды» — 11; `badge` — «Октябрь 2026»; `cards` — три разные карты №2, №3, №1 (заготовка ставит сама).

## Статистика меты (`meta.json`)

`node scripts/meta-stats.mjs yt-<тема>` (`yt-new` запускает сам) — Koloda Hearthstone API (`api.kolodahearthstone.com`, токен `KOLODA_API_TOKEN` в `video/.env`, необязателен). Для каждой колоды статьи находит архетип HSReplay по совпадению карт и пишет: `winrate` и `popularity` архетипа (% всех игр в Легенде EU за 7 дней), `deck.winrate`/`deck.games` самой сборки (точнее, если HSReplay объединил несколько сборок в архетип), `best`/`worst` — три лучших и худших матч-апа с винрейтом, `mulligan` — что оставлять в стартовой руке (% и винрейт), `trend` — популярность месяц назад и сейчас. Как использовать:
- тезис с цифрой: `{text: 'Винрейт 54,8 %', detail: 'Лучший в Легенде по данным HSReplay', at: …}` — только если в `vo` это тоже сказано;
- матч-апы `vs`: если статья о них молчит — можно взять 1–2 из `worst`/`best` (`verdict: 'bad'`/`'good'`), сказав о них в `vo`;
- сцена `mulligan` (гайды) — из `mulligan`;
- статья важнее: если цифры спорят со статьёй, в ролик идёт статья, расхождение — пользователю.

## Глаза: смотреть чужие ролики и отбирать геймплей (`scripts/eyes.mjs`)

- **Свои записи (главный источник геймплея):** пользователь пишет игры в OBS в `video/recordings/` (настройка — `recordings/README.md`) и во время игры жмёт «метку главы» сразу после удачного момента. `node scripts/rec.mjs` — новые записи → клипы `recordings/clips/<запись>-m<n>.mp4` вокруг каждой метки (−12…+3 с, со звуком игры; `--before/--after`); без меток — 8 самых активных моментов (`-a<n>`, кандидаты). Обзор `recordings/clips/index.md` — полоски кадров, смотреть Read и выбирать по тексту диктора. В ролик: `node scripts/rec.mjs take <клип> --name <имя> [--trim 2-9]` → `public/clips/<имя>.mp4` + паспорт («Геймплей: запись Манакоста»). Записи и клипы в git не идут, в git — только взятое в `public/clips`.
- **Найти геймплей с авторами:** `node scripts/eyes.mjs find "<запрос>" [--yt | --twitch] [--cc] [--days 30] [--n 10]` → `out/eyes/find-<запрос>.md` (+ `.json`): YouTube (поиск, лицензия каждого ролика, канал, просмотры, дата) и Twitch (самые просматриваемые клипы Hearthstone за `--days`: стример, кто нарезал клип, просмотры). Twitch по всей категории — с ключами `TWITCH_CLIENT_ID/SECRET` в `.env` (`--lang ru`); без ключей — по каналам (`--channels a,b` или `TWITCH_CHANNELS` в скрипте), клипы других игр отсеиваются. Колонка «права»: CC BY — можно; иначе — нужно согласие автора (ссылка на канал — там же).
- `node scripts/eyes.mjs look <url | файл> [--from 0 --to 300]` → `out/eyes/<имя>/report.md`: листы кадров с таймкодами, темп монтажа (склейки, средняя длина плана), активность по секундам и самые динамичные моменты — полоски по 6 кадров через 0,2 с (`moment-*.jpg`, смотреть Read): так разбирается, как устроен чужой переход или анимация, и где в геймплее самое интересное. Клипы Twitch — тоже.
- `node scripts/eyes.mjs scenes <url | файл> [--from 0 --to 600]` → `out/eyes/<имя>/scenes.md`: планы по склейкам (PySceneDetect) с полоской «начало · середина · конец» у каждого; ★ — план длиннее 8 с (кандидат на врезку). В своей записи без склеек «планы» — резкие смены картинки (розыгрыш, смена хода).
- `node scripts/eyes.mjs cut <url> --from 40 --to 52 --name <имя>` → `public/clips/<имя>.mp4` (1080p) + паспорт `.json` (источник, автор, кто нарезал клип, лицензия, согласие). Берёт: CC BY; чужое с согласием автора — `--permission "написал в Telegram 03.10, ответил да"` (текст сохраняется в паспорт); своя запись (OBS) — `--own`. Иначе — отказ. Во врезке `clip`: `credit` — из паспорта; вебкамеру и трекер стримера убрать `crop`.
- **Указание автора — не разрешение.** Клипы Twitch и обычные ролики YouTube без согласия автора в ролик не берём (монетизируемый канал: Content ID, жалобы). Смотреть можно что угодно (разбор приёмов).
- YouTube отвечает 403 на скачивание (`look`/`cut`/`scenes`) — устарел yt-dlp: `yt-dlp -U` (с согласия пользователя: качает новую версию с GitHub).

- Подача — живая, но спокойная: короткие фразы, паузы; `[warmly]` — тёплое начало, `[curious]` — интрига, `[pause]` — после точки. **Без `[excited]`** — диктор кричит.
- Порядок: (1) перенести старые `out/<id>/vo-raw/chunk-*`, `chunks.json` в `out/<id>/vo-raw/prev-<дата>/`; (2) `node scripts/vo-align.mjs <id> --prepare [--only hook,intro]` → `out/<id>/vo-raw/chunk-<n>.txt`; (3) текст каждого куска целиком — в `creative_generate_speech`; (4) `creative_get_flow_run_status` до `all_completed`, скачать `media[0].url` в `out/<id>/vo-raw/chunk-<n>.mp3` (`curl -s -o …`); (5) `node scripts/vo-align.mjs <id>` — режет куски на сцены, темп +6 %, время слов, обработка голоса; печатает «распознано иначе» — передать пользователю «послушать».
- **Дубли только ключевых фраз** (начало, объявление №1, финал): после `--prepare --only hook,deck-01,outro` каждый кусок записать 2–3 раза (каждый — отдельный вызов, `generations_count: 1`) и сохранить как `chunk-<n>.take-1.mp3`, `chunk-<n>.take-2.mp3`…; `node scripts/vo-takes.mjs <id>` мерит дубли (высота голоса против обычной для ролика, слова, услышанные непохоже, паузы), отбрасывает «поднятые» (крик), лучший копирует в `chunk-<n>.mp3` (`--dry` — только отчёт `vo-raw/takes-report.md`); дальше `vo-align.mjs <id>`. Весь ролик в нескольких дублях не писать — кредиты.
- Паузы внутри фразы проверить: `ffmpeg -hide_banner -i public/vo/<id>/<сцена>.mp3 -af silencedetect=n=-40dB:d=0.25 -f null -`.
- Субтитров в кадре с голосом нет — только `.srt` из `yt-export`.

## Грабли (на каждой уже спотыкались)

- **Медленное движение — только `transform`/`translate`/`scale`.** `left/top/width` Chrome округляет до пикселя у каждого элемента в свой момент — карты мелко дрожат (0,29 px шума → 0,02 после переноса постера в один слой с `transform`).
- Точки камеры зажимать в кадр заранее (`planCamera(…, view)`), не каждый кадр — иначе у края упор и рывок.
- `Sfx` не класть внутрь слоя под `CameraMotionBlur` — слой рисуется копиями, звук задвоится.
- Фразу-привязку не зашивать в код сцены (было: «на вершине» во вступлении роняло рендер других роликов) — только поле конфига с запасным вариантом.
- 60 к/с: время в «кадрах-30» через `useFrame()`, `Sequence`/звук × `useK()`.
- Кириллица: не прогонять файлы через PowerShell `Get-/Set-Content`. Правки с `\n`, `\s`, обратными кавычками через `node -e` в bash ломаются экранированием — такие куски писать инструментами Edit/Write.
- Не запускать prettier по файлам шаблона: стиль — длинные строки (≈ `--print-width 200 --single-quote --no-bracket-spacing --object-wrap collapse`), иначе переформатируется весь файл. Если испортил — копии до правок в `~/.claude/file-history/<сессия>/`.
- Проверка «ничего не сломал» при рефакторинге шаблона или конфига: `node scripts/yt-snap.mjs <путь/до>` до правки и `… <путь/после>` после — хэши должны совпасть (иначе `diff` двух json покажет, что поменялось).
- Без «нейросетевого почерка»: никаких свечений, искр, неона, тряски. Цифры — только из источника. Чужой геймплей — только CC BY с автором; `public/clips` — для проб.
- Деньги и необратимое: перед записью > нескольких сотен знаков — цена пользователю; коммит, push, публикация, удаление полного рендера — только по его слову.
