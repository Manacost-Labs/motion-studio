## Как заполнять конфиг (коротко; подробно — examples.md)

- **Порядок сцен** заготовка ставит сама: `hook` → `intro` → колоды с последнего места → `divider` перед №10 и №5 → №3–№1 → `manacostOutro`. Не переставлять.
- **`at`** (и `to`, `teaseAt`) — кусок текста `vo` дословно, 1–4 слова. По нему элемент появляется в момент, когда диктор это говорит.
- **Тезисы** `points`: 2–3, `text` ≤ 28 знаков (вывод, а не пересказ), `detail` ≤ 45. **Матч-апы** `vs`: *какие* показывать — только названные в статье (нет в статье — `vs: []`); их `at` — как у всех привязок, кусок `vo`, где диктор о них говорит. **Карты** `cards` — заготовка берёт из упоминаний; `ink: true` — 0–3 на колоду (больше трёх — предупреждение), только у карт, которые диктор называет главными, лучшими, ключевыми.
- **`teaseAt`** во вступлении — фраза, где диктор намекает на лидера («на вершине», «кто же на первом месте»): в этот момент появляются размытые постеры топ-3.
- **Числа** на экране (`value`, `results`, тезисы) — только из статьи. В `vo` — словами.
- **`pronounce`**: каждое сокращение в `vo` (ДК, ОТК, ДХ, имена с апострофом) — как читать. `yt-qa` перечислит недостающие.
- **Обложка** `thumb`: `title` — две строки, в каждой ≤ 14 знаков (буквы, пробелы и знаки; `\n` — перенос, не считается): «15 колод» — 8, «для Легенды» — 11; `badge` — «Октябрь 2026»; `cards` — три разные карты №2, №3, №1 (заготовка ставит сама).

## Проверки качества (инструменты)

- `yt-qa.mjs` — данные (TODO, привязки, текст диктора, длины, простои) и видео (громкость, пики, чёрные/застывшие кадры, рывки вне стыков, тишина).
- `yt-board.mjs <id> [сцена…] [--at 0.2,0.8] [--frames 74,100] [--scale 0.5]` — кадры сцен и листы; `--frames` — кадр от начала сцены в «кадрах-30».
- `cam-jitter.py <видео> <с> <длина>` (`.venv-vo/Scripts/python.exe`) — плавность камеры: шум < 0,06 px — ровно, > 0,1 — дрожь.
- `yt-snap.mjs <префикс> [id…]` — слепок данных композиций (канонический JSON + sha1) для сверки до/после правок.
- Резкие смены кадра: `ffmpeg -i <видео> -an -vf "scale=432:-2,select='gte(scene,0)',metadata=print:key=lavfi.scene_score:file=-" -f null -` — всплески > 0,06 допустимы только на стыках сцен и заставках топ-3.

## Грабли (на каждой уже спотыкались)

- **Медленное движение — только `transform`/`translate`/`scale`.** `left/top/width` Chrome округляет до пикселя у каждого элемента в свой момент — карты мелко дрожат (0,29 px шума → 0,02 после переноса постера в один слой с `transform`).
- Точки камеры зажимать в кадр заранее (`planCamera(…, view)`), не каждый кадр — иначе у края упор и рывок.
- `Sfx` не класть внутрь слоя под `CameraMotionBlur` — слой рисуется копиями, звук задвоится.
- Фразу-привязку не зашивать в код сцены (было: «на вершине» во вступлении роняло рендер других роликов) — только поле конфига с запасным вариантом.
- 60 к/с: время в «кадрах-30» через `useFrame()`, `Sequence`/звук × `useK()`.
- Кириллица: не прогонять файлы через PowerShell `Get-/Set-Content`. Правки с `\n`, `\s`, обратными кавычками через `node -e` в bash ломаются экранированием — такие куски писать инструментами Edit/Write.
- Не запускать prettier по файлам шаблона: стиль — длинные строки (≈ `--print-width 200 --single-quote --no-bracket-spacing --object-wrap collapse`), иначе переформатируется весь файл. Если испортил — копии до правок в `~/.claude/file-history/<сессия>/`.
- Проверка «ничего не сломал» при рефакторинге шаблона или конфига: `node scripts/yt-snap.mjs <путь/до>` до правки и `… <путь/после>` после — хэши должны совпасть (иначе `diff` двух json покажет, что поменялось).
- Без «нейросетевого почерка»: никаких свечений, искр, неона, тряски. Цифры — только из источника. Чужой геймплей — только CC BY с автором; `public/clips` — для проб.
- Деньги и необратимое: перед записью > нескольких сотен знаков — цена пользователю; коммит, push, публикация, удаление полного рендера — только по его слову.
