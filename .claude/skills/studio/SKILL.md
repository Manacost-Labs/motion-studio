# Студия: вход для любого ролика

Все команды — из папки `video/`. Архитектура, слои, конвейер, закрепление и эталоны — `video/STUDIO.md`. Реестр студий — `video/src/studios/studios.json`, реестр роликов — `video/src/studios/README.md`.

## 1. Определи направление и загрузи его навык

| Задача | Навык | Студия |
|---|---|---|
| Реклама HearthPulse, новая версия рекламы, анонс функции сайта | `hearthpulse-video` | `hp-ads`, `hp-features` |
| YouTube Манакоста по Hearthstone: топ колод, гайд, обзор меты | `manacost-youtube` | `manacost-youtube` |
| YouTube по League of Legends: обзор патча, гайд, тир-лист, стиль-кадры, данные LoL | `lol-youtube` | `lol-youtube` (до шаблона: ждёт выбора стиль-кадра) |
| Другая игра, другой канал или площадка | `studio-new-direction` | пока нет |

Полная таблица «направление → навык → студия → игра → вкус» — корневой `CLAUDE.md`. Неясно, какое направление, — один вопрос пользователю. До начала работы прочитать не больше трёх файлов: навык направления, `video/TASTE.md` и вкус направления из `video/taste/`.

## 2. Общий конвейер

бриф → заготовка → данные → кадры → голос → **фрагмент → «да» пользователя** → полный рендер → `release.mjs` → сдача. Таблица этапов с воротами — `video/STUDIO.md`, «Конвейер ролика»; конкретные команды — в навыке направления.

- Спорный вид или новый приём — фрагментом 10–45 с (`render.ps1 -Draft -Frames A-B`) до массовой правки и до долгого рендера.
- Долгий рендер — в фоне (`run_in_background`) с `-Notify`; по окончании — проверка и сообщение пользователю.
- Отзыв пользователя — строка в `video/taste/<направление>.md` (формат — `video/taste/README.md`).

## 3. Проверки качества

| Команда | Что проверяет | Область |
|---|---|---|
| `npx tsc --noEmit -p .` | типы (Stop-хук делает сам после каждого хода) | общий |
| `node scripts/check-layers.mjs [--strict]` | импорты против слоёв (`video/STUDIO.md`) и детерминизм кадра (`Math.random(`, `Date.now(` и т. п. в `src/` — нельзя); без флага — отчёт, `--strict` — код 1 при новых нарушениях; Stop-хук и pre-commit вызывают `--strict` — нарушение не даст закончить ход и закоммитить | общий |
| `node scripts/doc-check.mjs` | пути и команды в документах и навыках существуют | общий |
| `node scripts/doctor.mjs` | ffmpeg, yt-dlp, Chrome, `.venv-vo`, ключи в `.env` «есть/нет» (значения не печатает) | общий |
| `node scripts/yt-qa.mjs <id> [--no-video]` | данные (TODO, привязки, текст диктора, пороги `LIMITS` канала, главы, SEO), файлы, видео (громкость, цвет bt709, рывки, тишина, пробные врезки) | YouTube |
| `node scripts/yt-lint.mjs <id>` | раскладка: текст за краем, текст на тексте; ⚠ читаемость и время чтения надписей | YouTube |
| `node scripts/yt-golden.mjs <id>` и `… --dir qa/golden-joints` | изменилась ли картинка сцен и стыков против эталонов | YouTube |
| `node scripts/judge.mjs <id>` | смысл: матч-апы и тезисы против статьи (бэкенд `agent` без ключей) | YouTube |
| `node scripts/release.mjs <id>` | всё к выпуску (сам запускает `yt-qa` и `yt-golden`, читает `judge.json`) → `out/<id>/release.md` + `out/<id>/release.json` | YouTube |
| `node scripts/check-ads.mjs` | закреплённая реклама не изменилась | реклама |
| `.\scripts\qa.ps1 <видео> -Cuts <кадры>` | рывки готового видео вне стыков | реклама |
| `.venv-vo/Scripts/python.exe scripts/ears.py --video <файл>` | звуки громче обычного на 6+ LU | общий |

Флаги, выходы, бэкенды судьи, пороги — `reference/quality.md`. Каталог всех команд с областью и тратами — `reference/tools.md`.

## 4. Готово, когда

- **YouTube:** `node scripts/release.mjs <id>` — **ни одного ❌** (вердикт «Технически готово — ждёт человека»); ручные пункты пройдены вместе с пользователем, он сказал «да» на фрагменте — и только по его слову `release.mjs <id> --approved` («Готово к выпуску (одобрено человеком)»). Самому `--approved` не ставить.
- **Реклама и обзоры:** обе ориентации отрендерены, `qa.ps1` по стыкам чист (всплески только на стыках), `check-ads.mjs` зелёный, пользователь сказал «да».
- Файлы переданы пользователю, строка в реестре `video/src/studios/README.md` обновлена, коммит **предложен** (не сделан).

## 5. Деньги и необратимое

- **Кредиты.** Перед любой тратой — `node scripts/credits.mjs [--need N]` и цена пользователю; тратить только после «да». ElevenLabs ≈ 1 кредит за знак (ролик 8 мин ≈ 7–8 тыс.), Higgsfield — по смете (`reference/higgsfield.md`). Один вызов — одна генерация; «на всякий случай» не повторять.
- **TypeSafe JEV** (бэкенд судьи) — только пилот: ключ `TYPESAFE_API_KEY` в `video/.env` кладёт сам пользователь; данные уходят в США — отправлять только публичный текст статьи и сценария. Без ключа работает бэкенд `agent`.
- **OpenRouter** (бэкенд судьи `openrouter`, визуальный критик `--visual`) — платно: `judge.mjs` сам печатает смету и ничего не шлёт; смету — пользователю, `--yes` — только после «да».
- **Коммит:** готовый этап — предложить; коммит, тег `freeze-<дата>`, push — только по слову пользователя. `--no-verify` — только по прямой просьбе.
- **Эталоны:** `yt-golden.mjs <id> --approve [сцена…]` и `check-ads.mjs --update <папка>` — только после «да» на фрагменте.
- **Не удалять** рендеры, записи, ассеты и код (в том числе «мёртвый») без слова пользователя: реклама и пробы — живые направления, не мусор.
- `video/.env` не выводить, ключи не передавать в аргументах и логах.
- Чужой геймплей — только CC BY с автором или с согласием автора (`reference/eyes-ears.md`). `yt-dlp -U` качает с GitHub — с согласия пользователя.

## 6. Куда класть новое

Таблица — `video/STUDIO.md`, «Куда класть новое»; слои и правила импортов — там же. Коротко:

- общее (время, голос, звук, эффекты, проверки) — `video/src/core`; приём стиля — `video/src/looks/<стиль>`; данные и сцены игры — `video/src/games/<игра>`; ссылки, финал, голос и оговорка канала — `video/src/brands/<канал>/channel.ts`; студия-канал только собирает их (`channel.ts`, `videos.ts`);
- новая сцена — файл сцены (компонент + `defineScene`) и строка в `scenes` канала; тип конфига ролика выводится из канала, чужой `kind` не пройдёт `tsc`;
- не импортировать из чужой студии и из чужого ролика; ролик YouTube импортирует только `../channel`;
- пороги — только в источнике: общие `VIDEO_LIMITS` (`video/src/core/qa/limits.ts`), игры — `video/src/games/<игра>/data/audit.ts`, канала — `LIMITS` в `channel.ts`;
- новый скрипт — с областью в шапке, скрипт игры — в `scripts/games/<игра>/`; существующие скрипты не переименовывать; пути в `public/` не двигать.
