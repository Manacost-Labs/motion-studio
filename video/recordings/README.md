# Свои записи Hearthstone

Сюда OBS пишет записи игр; клипы из них режет `node scripts/rec.mjs` (из `video/`). Сами записи и клипы в git не идут.

Область — только Hearthstone (YouTube Манакоста): профиль OBS, `rec.mjs` и подпись «запись Манакоста» рассчитаны на него. Для другой игры — свой профиль OBS и свой README в `recordings/<игра>/` (заводит навык `studio-new-direction`).

## OBS уже настроен (04.10.2026)

В OBS — профиль **«Hearthstone»** и коллекция сцен **«Hearthstone»** (открываются при запуске):

- сцена — захват игры `Hearthstone.exe` со звуком только игры (звук рабочего стола и микрофон в эту коллекцию не входят), вписан в кадр;
- запись — в эту папку, **«Гибридный MP4»** (только он хранит метки), 1920×1080, 60 к/с, качество «Неотличимое», кодировщик NVENC;
- **F10** — начать / остановить запись, **F9** — метка главы. Клавиши работают и когда в фокусе игра.

Проверено: запись по F10, метки по F9 попадают в файл, `rec.mjs` режет по ним клипы. Прежние настройки — профиль и коллекция «Безымянный» (захват окна Chrome) — на месте: «Профиль» и «Коллекция сцен» в меню OBS. Копия настроек до изменений — `%APPDATA%\obs-studio-backup-2026-10-04`.

Трекер колоды (HDT и т. п.) на время записи лучше выключить — иначе его придётся обрезать в кадре.

## Во время игры

Запустить OBS, в игре нажать F10 — запись пошла. Сразу **после** удачного момента — летал, большой розыгрыш, комбо, неожиданный поворот — нажать F9. В конце — F10. Скрипт вырежет 12 секунд до метки и 3 после. Забыли нажать — не страшно: запись без меток он просмотрит сам и предложит самые активные моменты.

## Дальше

- `node scripts/rec.mjs` — новые записи → клипы в `clips/` и обзор `recordings/clips/index.md` (у каждого клипа полоска кадров).
- `node scripts/rec.mjs take <клип> --name <имя> [--trim 2-9] [--tight]` — клип в ролик (`public/clips/<имя>.mp4`, подпись «Геймплей: запись Манакоста»); `--tight` срезает простой в начале и конце клипа.
- `node scripts/rec.mjs idle <запись | клип>` — где простой (см. ниже).
- Ник соперника виден в кадре — если нужно, скажите, добавим размытие.

## Простой: `rec.mjs idle`

Ход соперника, ожидание, муллиган — «мёртвое» время. Музыка игры звучит всегда, поэтому по тишине его не найти — ищем по **движению в кадре** ([auto-editor](https://github.com/WyattBlue/auto-editor), `levels --edit motion`: доля пикселей, изменившихся с прошлого кадра).

```
node scripts/rec.mjs idle <запись.mp4 | имя в recordings/ | клип> [--threshold 0.08] [--min-idle 3] [--margin 1]
```

Отчёт — `recordings/clips/<имя>.idle.md` (+ `.json`): активное и простой по порядку (м:сс, длина, среднее движение), итоги, метки глав — в простое ли метка, сколько простоя в клипе вокруг неё (−12…+3 с) и каким он будет с `take --tight`. **Ничего не режет и не удаляет** — только подсказки; решает человек.

- `--threshold` — окно 0,5 с (медиана) ниже порога — стол стоит. Курсор и короткое наведение на карту (всплыла подсказка) двигают кадр слабо, ниже порога: ожидание с курсором остаётся простоем.
- `--margin` — поле с каждой стороны простоя, которое остаётся активным: медленная анимация карты и хвост эффекта не попадут в простой.
- `--min-idle` — короче (после полей) не показывать.

Порог 0.08 подобран 10.10.2026 на 18-минутном геймплее Hearthstone с YouTube (30 к/с, с трекером) и клипе с вебкамерой (60 к/с): стоящий стол — 0.03–0.06, наведение на карту — до 0.075; розыгрыш, атака, «Ваш ход», выбор карты — 0.09 и выше. Кадрами проверено: в простой попали ход соперника без действий, муллиган, соперник выбирает карту. На первой своей записи OBS посмотреть отчёт и пару отрезков; не так — поправить `--threshold` и это число в `scripts/rec.mjs`.

Скорость: ~30 с на 18 мин 1080p30, запись 1080p60 на час — около 5 мин в первый раз; повторный запуск мгновенный (кэш auto-editor в `%TEMP%\ae-31.7.2`).

**Установка** (один раз, из `video/`; проверяет `node scripts/doctor.mjs`). На PyPI auto-editor старый (29.3.1), поэтому бинарник релиза 31.7.2 с GitHub (лицензия Unlicense), в `tools/` — в git не идёт:

```
mkdir tools\auto-editor
curl -L -o tools/auto-editor/auto-editor.exe https://github.com/WyattBlue/auto-editor/releases/download/31.7.2/auto-editor-windows-x86_64.exe
certutil -hashfile tools\auto-editor\auto-editor.exe SHA256
```

SHA256 должен быть `c5dd8d44a92e9b5fbce13aacea92d02436ea24f9f4c6177a6a9d851801fb74c3` (44 701 696 байт). Другая версия — синтаксис `--edit` и вывод `levels` могли измениться: сначала проверить на клипе.
